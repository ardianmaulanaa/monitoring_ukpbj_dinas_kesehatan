# Data Dictionary SIMUKPBJ

> Generated by audit of `schema.prisma` on 2026-10-17. `?` means nullable. Defaults and constraints shown are schema-level facts.

## Core models

### User / Role / UserRole

| Field | Type | Rule | Meaning |
|---|---|---|---|
| `User.id` | String Char(36) | PK, UUID | user identity |
| `email` | VarChar(180) | required, unique | login identifier |
| `passwordHash` | VarChar(255) | required | bcrypt hash, never expose |
| `status` | `UserStatus` | default ACTIVE | account state |

### RencanaUmumPengadaan

Central record for planning, verification, SIRUP, and current E-Purchasing implementation.

| Field group | Important fields | Type/rule | Meaning |
|---|---|---|---|
| Identity | `id`, `kodeRup`, `namaPaket` | UUID PK; kode unique; name max 220 | one RUP package |
| Scope | `unitPengusul`, `unitBidang?`, `tahunAnggaran`, `sumberDana` | required except unitBidang | filtering/access/reporting |
| Budget | `pagu`, `estimasiHargaSatuan?`, `totalEstimasi?` | Decimal(18,2) | budget/reference values |
| Method | `metodePengadaan` | enum | TENDER/NON_TENDER/E_PURCHASING/PENGADAAN_LANGSUNG/SWAKELOLA |
| Planning | program/kegiatan/subKegiatan, need/spec/justification fields | nullable text/varchar/decimal | proposal content |
| Workflow | `statusUsulan`, `statusSirup` | enum, defaults DRAFT/BELUM_INPUT | planning and RUP states |
| Submission | `submittedBy?`, `submittedAt?`, verification/revision fields | nullable | actors and timestamps |
| Catalog product | product/platform/category/link/price fields | nullable; length constraints | chosen catalog data |
| Provider/negotiation | provider fields, offer/final price/status | nullable | selection outcome |
| Contract/SP | SPPBJ, SP, SPK, SPMK number/date/status | nullable strings | contractual evidence |
| Delivery/inspection | delivery, functional test, inspection, BAST fields | nullable strings | execution evidence |
| Payment | document/payment status, `nilaiPembayaran?`, invoice/faktur/date | Decimal + strings | realized payment |
| Stage marker | `statusTransaksiKatalog?` | VarChar(80) | current E-Purchasing marker |
| Audit timestamps | `createdAt`, `updatedAt` | now/updatedAt | record input/update time |

Catalog length limits: product 220, brand 160, unit 60, display/category 160/120, product link 255, platform 80. Dates in the catalog workflow are currently strings up to 120 characters.

### UsulanVerificationHistory

`id` PK; `proposalId` required FK -> RUP with cascade; actor ID/name/role; action; old/new `StatusUsulan`; note/checklist; `createdAt`. It is the authoritative per-proposal approval history, distinct from global `AuditLog`.

### Generic execution models

| Model | Key fields | Relations/business meaning |
|---|---|---|
| `PaketPengadaan` | unique `kodePaket`, year/source/method, pagu/HPS, `PaketStatus` | generic procurement package parent |
| `Kontrak` | unique `nomorKontrak`, value/dates/`KontrakStatus`, optional `paketId` | generic contract; schema has index but no declared relation to PaketPengadaan |
| `RealisasiBelanja` | optional package/contract IDs, source/year/value/date | generic spending transaction |

| `SerahTerima` | unique document no., optional package/contract | handover record |
| `RisikoMitigasi` | risk, level, mitigation, PIC/deadline/status | package risk |
| `TimelineEvent` | optional package/contract, stage/dates/status | schedule event |
| `AuditChecklist` | package/document pair unique | document readiness |

### Masters/support

`SumberDana` (unique code, name, active); `DataBarang`; `Penyedia`; `KlinikKonsultasi`; `DokumenTemplate`; `LaporanTersimpan`; and `AuditLog`. Refer to schema for complete field lengths; changes to any field require updating this dictionary.

## Dashboard mapping

| Metric | Model/field | Aggregation and date |
|---|---|---|
| Total package | RUP `id` | row count in active scope |
| Total pagu | RUP `pagu` | sum |
| Realisasi | RUP `nilaiPembayaran` | sum; monthly date `tanggalPembayaranEp` |
| Contract value | RUP `hargaNegosiasiKatalog` + contract/SP evidence | sum valid pairs |
| Efficiency | RUP `pagu`, `hargaNegosiasiKatalog` | difference only for valid paired rows |
| Monthly package histogram | RUP `createdAt` | count by record-input month; not planning date |
| Monthly pagu | RUP `pagu`, `createdAt` | sum by input month, cumulative in UI |
| Funding donut | RUP `sumberDana`, `pagu` | group + sum |
| Monthly realization | RUP `nilaiPembayaran`, `tanggalPembayaranEp` | valid parsed date/year, cumulative in UI |
| Current stage | workflow/status/evidence fields on RUP | one furthest valid stage per row |
